# Unit Tests Move From Karma To Vitest

Dependabot alert #80 (minimatch < 11.0.1, denial of service) could not be fixed
by an override: Karma 6.4.4, the latest release, calls minimatch 3 as a bare
function and crashes (`mm is not a function`) on minimatch 11. Karma and
karma-coverage were the only users of minimatch, so the unit tests now run on
Vitest and both are gone.

## What changed

- `test` target in `angular.json`: `@angular/build:karma` → `@angular/build:unit-test`
  with `runner: vitest`, real Chromium through Playwright (`@vitest/browser-playwright`;
  jsdom has no `matchMedia`), `setupFiles: src/test-setup.ts`, and the same 50% coverage
  thresholds as `karma.conf.js` had.
- Removed `karma`, `karma-chrome-launcher`, `karma-coverage`, `karma-jasmine`,
  `karma-jasmine-html-reporter`, `jasmine-core`, `@types/jasmine` and `karma.conf.js`.
  Added `vitest` and `@vitest/browser-playwright`.
- The Jasmine specs were converted with `ng generate refactor-jasmine-vitest` (spies
  → `vi.fn`/`vi.spyOn`, `jasmine.clock` → fake timers), then four mock objects got an
  `as unknown as MockedObject<…>` cast and `window.open` mocks return `null`.
- `src/test-setup.ts` restores mocks and real timers after every test. Jasmine did this by
  itself; Vitest does not, so a stubbed `window.matchMedia` leaked into later specs.
- `overrides.minimatch` replaced by `overrides.chrome-launcher: ^1.2.2`. `@lhci/cli` pulled
  `chrome-launcher@0.13` → `rimraf@3` → `glob@7` → minimatch 3; version 1.x (what Lighthouse
  already uses) has no such chain. minimatch is no longer in the lockfile.
- CI installs Playwright's Chromium for the unit-test job and runs `npm test -- --watch=false --coverage`.

All 184 tests pass, as before the move.
