# Fail the deployment build when the analytics ID is missing

Closes finding 7 of `docs/security-audit-2026-10-26.md`, the half that was
actually dangerous: `scripts/inject-env.js` used to fall back to a hardcoded,
*live* measurement ID (`G-E3T7KDSRKW`) whenever `GOOGLE_ANALYTICS_ID` was
unset or malformed. That fallback was this site's own GA property, so any
build without the env var — a fork, a misconfigured Vercel project, a local
`npm run build` served from a laptop — silently reported its visitors into
this site's analytics. The comment in the old script described the value as a
convenience for local builds; in practice it was a shared sink for anyone
building this codebase.

Supersedes the "**Fallback:**" bullet in
`20260727-205542-google-analytics-1.md`, which described the old behaviour.

## What changed

`scripts/inject-env.js` now has three outcomes instead of two:

| Situation | Result |
|---|---|
| `GOOGLE_ANALYTICS_ID` (or the `GOOGLE_ANALYTICS` alias) is a valid `G-…` ID | substituted, exactly as before |
| Vercel build (`VERCEL=1`), value missing or invalid | **`exit 1`**, dist left untouched, both the reason and the fix printed |
| Any other build, value missing or invalid | builds with the inert placeholder `G-XXXXXXXXXX` and warns loudly |

Details worth knowing:

- **`VERCEL=1` is the deploy signal**, not `NODE_ENV` or CI. Vercel sets it for
  preview and production builds alike, and both are real deployments, so both
  fail. This repo's own GitHub Actions build job (a compile check, not a
  deploy) is unaffected and keeps passing without any secret configured.
- **`ALLOW_MISSING_ANALYTICS=1` is the deliberate opt-out.** Without it a fork
  that wants no analytics at all could never deploy — the build would fail
  every time for want of a variable it never intended to set. The failure
  message names this variable so the way out is discoverable from the error
  alone.
- **`G-XXXXXXXXXX` is not a real property.** `gtag.js` still loads and
  initialises harmlessly; no hits reach anywhere, and no third party receives
  this site's traffic.
- **Validation now happens before any file is written.** Previously the
  "warn if the value came from the fallback" loop ran over `REPLACEMENTS` and
  then a second loop wrote every file; a failure between them could leave a
  half-substituted `dist/`. Resolution and validation are now one pass ahead of
  the write pass, so a build that exits 1 leaves the output exactly as it was.
- Per-replacement `pattern` / `hint` / `placeholder` replace the single
  `fallback` string, keeping the `REPLACEMENTS` table shape for anything added
  later.
- Messages are `console.error` for the fatal path (so they land on stderr where
  a build log picks them up) and `console.warn` for the placeholder path.

## Verification

`node --check` plus a throwaway `dist/` tree containing the placeholder in
`index.html` and a nested `projects/index.html`, run under each combination:

| Case | Exit | Result |
|---|---|---|
| local, no env | 0 | `G-XXXXXXXXXX` in both files, warning printed |
| `VERCEL=1`, no env | 1 | files untouched (placeholders intact), refusal message |
| `VERCEL=1`, `GOOGLE_ANALYTICS_ID=G-ABC123XYZ` | 0 | ID substituted |
| local, `GOOGLE_ANALYTICS_ID=not-a-ga-id` | 0 | placeholder + "not a valid value" warning |
| `VERCEL=1`, `ALLOW_MISSING_ANALYTICS=1` | 0 | placeholder, warning |
| local, `GOOGLE_ANALYTICS="  'G-ALIAS9' "` | 0 | `G-ALIAS9` (alias + quote/whitespace trimming still work) |

No `ng build` was run (no `node_modules` in this worktree); the changed code is
the postbuild script only, and the cases above exercise each branch of it.
