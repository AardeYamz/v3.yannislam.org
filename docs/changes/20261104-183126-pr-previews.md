# Serve Every Open PR At prs.yannislam.org/pr-N/

Vercel already deploys each branch to its own `*.vercel.app` URL, which sits behind Deployment Protection and changes
per branch. The Cloudflare repos instead publish every open PR under one stable host at `/pr-<number>/`. This gives
this repo the same.

## How it works

Vercel aliases hostnames, not paths, so the previews cannot be one alias per PR. Instead
[`pr-previews.yml`](../../.github/workflows/pr-previews.yml) publishes **all** open PRs together, as the Cloudflare
deploy does:

1. `list`: open, same-repo PRs (forks are never built; Dependabot runs get no secrets and are skipped, but their PRs
   are included by the next run).
2. `build` (matrix, no secrets): each PR's head is built with `npm run build -- --base-href /pr-<n>/` and uploaded as
   artifact `pr-<n>`. A PR that fails to build does not stop the others.
3. `deploy` (holds `VERCEL_TOKEN`, runs no PR code): downloads the artifacts into `site/pr-<n>/`, adds an index page (styled with the shared yl-theme: header, section title and light/dark toggle, loaded from `theme.yannislam.org` at the version pinned in `theme.json`) and a
   `vercel.json` (noindex, no-referrer, `cleanUrls`), and runs `vercel deploy site --prod` against a separate static
   project. Each deploy replaces the last, so closed PRs disappear on the next run.
4. Comments `https://prs.yannisl.am/pr-<n>/` (short form; redirects to `https://prs.yannislam.org/pr-<n>/` via the `yannisl.am` catch-all in personal-dns) on each PR, editing its own marked comment in place.

Runs on PR open/sync/reopen/close only. It deliberately has no `push` or `workflow_dispatch` trigger: those runs can write
the default branch's Actions cache, and this workflow builds PR code, which CodeQL reports as cache poisoning. A
`pull_request` run only writes its own merge-ref scope. The cost is that previews are not refreshed when `main` moves or
when `sync-prs.yml` merges it into PR branches (a `GITHUB_TOKEN` push starts no run); close and reopen any PR, or push to
one, to rebuild them all.

## One-time setup (not in the repo)

1. Vercel: create a project (e.g. `v3-prs`), framework **Other**, **not** connected to Git. Add the domain
   `prs.yannislam.org` to it. Set Deployment Protection to *Vercel Authentication* if previews should not be public
   (the Cloudflare ones are behind Access).
2. DNS (personal-dns repo): `prs` CNAME to `cname.vercel-dns.com` (or whatever Vercel shows for the domain).
3. Repo variables: `VERCEL_ORG_ID` (`team_iQIC40j10BmtJRl4XP2IrTaI`) and `VERCEL_PREVIEWS_PROJECT_ID` (the new project's id).
   The existing `VERCEL_TOKEN` secret is reused.

## Limits

- The previews project's `vercel.json` applies, not the site's: no CSP and no long-cache headers on previews.
- Only prerendered files are served; there is no SSR fallback for routes the build did not prerender.
- The Angular service worker's scope follows the base href, so each preview's is limited to its own `/pr-N/`.
