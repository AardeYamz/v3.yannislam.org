# Preconnect hints for Google Analytics

## Context

`src/index.html` loads Google Analytics via `<script async
src="https://www.googletagmanager.com/gtag/js?id=...">` (see
`documentation/google-analytics.md`). Without a hint, the browser only
starts DNS/TCP/TLS setup for `googletagmanager.com` once it actually parses
that `<script>` tag — connection setup happens serially with everything
else in `<head>` instead of overlapping it.

## What changed

Two `<link rel="preconnect">` tags added to `src/index.html`, right above
the gtag `<script>` tag (top of `<head>`, after `<meta charset>`):

```html
<link rel="preconnect" href="https://www.googletagmanager.com" crossorigin>
<link rel="preconnect" href="https://www.google-analytics.com" crossorigin>
```

`crossorigin` is included on both because the browser only reuses a
preconnected connection if the eventual request uses matching CORS mode —
without it, `<link rel="preconnect">` opens a connection that the actual
(CORS) script/beacon request can't reuse, wasting the hint.

## Why two origins

`googletagmanager.com` only serves the `gtag.js` script itself. Once
loaded, `gtag.js` sends its actual pageview/event hits to a *second*
origin, `www.google-analytics.com` (GA4's collect endpoint) — this is
gtag.js's standard, well-documented behavior, not specific to this site.
Preconnecting only the first origin would still leave the second
connection to be set up cold, later in the page lifecycle, right when the
first hit is about to be sent. No other origin is contacted by this
integration (confirmed against `documentation/google-analytics.md`, which
documents the site's Analytics setup end-to-end), so no further preconnects
were added.
