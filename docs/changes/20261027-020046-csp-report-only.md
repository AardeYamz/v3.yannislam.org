# CSP in report-only mode, plus COOP

Addresses finding 1 of `docs/security-audit-2026-10-26.md` ("No
Content-Security-Policy"). Two headers are added to the global `/(.*)` block in
`vercel.json`:

- `Content-Security-Policy-Report-Only` — the target policy, reporting only.
  Nothing is blocked yet; violations surface in the browser console (there is
  no report collector configured — see "Before enforcing").
- `Cross-Origin-Opener-Policy: same-origin` — enforcing from day one. Safe
  here: the site opens no cross-origin popups, and the resume button opens a
  same-origin PDF on the same site.

## The policy, and why each directive

```
default-src 'self';
script-src 'self' 'unsafe-inline' https://www.googletagmanager.com;
style-src 'self' 'unsafe-inline';
img-src 'self' data: https:;
font-src 'self';
connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com
             https://www.googletagmanager.com;
frame-src https:;
worker-src 'self';
manifest-src 'self';
object-src 'none';
base-uri 'self';
form-action 'none';
frame-ancestors 'none'
```

- **`script-src` — `'unsafe-inline'` is temporary, and is the one real
  weakness.** `src/index.html` carries an inline gtag bootstrap that contains
  the measurement ID, which `scripts/inject-env.js` substitutes at build time.
  Its hash therefore changes per build (and differs between a local build's
  inert placeholder and production), so a hash cannot live in the static
  `vercel.json`. Enforcing without `'unsafe-inline'` requires moving that
  bootstrap into a same-origin `.js` asset — the ID can be read from the gtag
  script's own URL (or a `<meta>` tag, which `inject-env.js` already knows how
  to substitute) — after which `script-src 'self' https://www.googletagmanager.com`
  is enough. Until then the CSP still blocks third-party script *origins* and
  framed/embedded objects, just not inline script.
- **`style-src` needs `'unsafe-inline'` permanently**, or at least until
  Angular's component styles are emitted with a nonce: Angular injects each
  component's styles as an inline `<style>`, and templates use inline `style`
  attributes (`workhistory.component.html`'s `style='color: inherit'`).
- **`img-src https:`** — `config.json` hotlinks organization logos from
  third-party hosts (`cdn.voya.com`, `pbs.twimg.com`, `graph.facebook.com`,
  `corporate.homedepot.com`, `www.thayer.org` today). `data:` covers the
  generated logo-fallback SVG.
- **`connect-src 'self'`** covers the `@vercel/analytics` and
  `@vercel/speed-insights` beacons, which post to `/_vercel/*` on the same
  origin; the explicit hosts are GA4's collection endpoints.
- **`frame-src https:`** — the hover preview frames arbitrary links from
  `config.json`. Broad by design, same as `img-src`.
- **`frame-ancestors 'none'`** is ignored in report-only policies (the spec
  disallows reporting it); `X-Frame-Options: DENY` is what actually enforces
  clickjacking protection today, and this directive takes over when the header
  is switched to enforcing.
- **`upgrade-insecure-requests` is deliberately absent.** Chrome logs "The
  Content Security Policy directive 'upgrade-insecure-requests' is ignored
  when delivered in a report-only policy" on every policy parse, and HSTS with
  `includeSubDomains; preload` already upgrades at the transport level. Add it
  back only if the header is enforced and a non-HSTS deployment target appears.

## Verification

`npm run build`, then the built `dist/v3.yannislam.org/browser` was served
locally with the header block read straight out of `vercel.json` (a throwaway
Node server, deleted afterwards), and loaded in Chromium at `/`, `/projects/`
and `/aardeyamz`:

- **Zero CSP violations** in the console on all three routes.
- **Nothing silently broken:** body background `rgb(19, 31, 49)` (theme CSS
  applied), Calibre fonts reported `loaded`, 127 images across 6 external hosts
  with 0 broken, `window.dataLayer` populated (inline gtag bootstrap still
  runs), service worker controlling the page, and the hover preview created its
  `about:blank` iframe.
- **The harness itself was proven live**, so "no violations" means something:
  appending a `<script src="https://example.org/...">` produced
  `[Report Only] Refused to load the script … script-src`, and an `https:`
  iframe (`example.com`) loaded with no violation, confirming `frame-src https:`
  is doing what it should.
- The two `/_vercel/insights/script.js` and `/_vercel/speed-insights/script.js`
  errors in the local run are the toy server returning `index.html` for
  endpoints only Vercel serves; they are not CSP violations.

## Before enforcing

1. Decide the `'unsafe-inline'` question for `script-src` (externalize the gtag
   bootstrap, or accept it).
2. Add a `report-to`/`report-uri` collector if violations should be collected
   automatically rather than read from devtools — nothing is sent anywhere
   today.
3. Rename the header to `Content-Security-Policy`.
4. Re-check on the real origin: Vercel serves `/_vercel/*` and the prerendered
   routes with its own caching, neither of which the local harness reproduced.
